# NOCL

JAX/Haiku implementation for **Neural Operator-based Curriculum Learning for
Physics-Informed Neural Networks**, by Lingshi Meng, Haosen Shi and Sinno Jialin Pan.

This repository contains the NOCL implementation for two experiments:

| Experiment | Protocol | Target |
| --- | --- | --- |
| Convection | Derivative-constrained high-frequency example | alpha = 3 |
| Reaction–diffusion (RD) | Rebuttal experiment with sine initial condition and zero Dirichlet boundaries | nu = 4, rho = 5 |

Training points and reference solutions are generated by the code. No external
dataset is required.

## Installation

The validated environment uses Python 3.12.7, JAX 0.5.0 and an NVIDIA RTX 4090
with 24 GB memory.

```bash
git clone https://github.com/windindicator/NOCL-NeurIPS2026.git
cd NOCL-NeurIPS2026
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

For the validated NVIDIA CUDA 12 environment, install the pinned GPU dependencies:

```bash
python -m pip install -e '.[cuda12]'
python -c 'import jax; print(jax.devices())'
```

Full training is intended for a GPU. Use `--gpu 0` or `--gpu 1` to select a
physical GPU; `--gpu -1` selects CPU.

## Repository Layout

```text
nocl_minimal/          Models, physics losses, curriculum transfer and training
experiments/           Training, evaluation, plotting and comparison entry points
experiments/configs/   Two experiment configurations
experiments/records/   RD protocol and paper/rebuttal reference values
```

## Run the Experiments

Run Convection:

```bash
python -m experiments.run --config experiments/configs/convection.json \
  --gpu 0 --output results/convection/seed42
```

Run the rebuttal RD experiment:

```bash
python -m experiments.run --config experiments/configs/rd.json \
  --gpu 0 --output results/rd/seed42
```

Both configurations use seed 42. Use `--seed 43` to change it, and choose a new
output directory for each run. Training saves every curriculum PINN; add
`--save-operator` to also save the final FNO weights.

For a short functionality check, add `--smoke`. Convection smoke runs use smaller
models and grids. RD smoke runs retain the full architecture and all 25 curriculum
levels with two updates per phase. Smoke results are not benchmark results.

## Outputs

Training writes `metrics.json` and `checkpoints/pinn_*.npz` to the chosen output
directory. RD also writes `progress.json` and `final.json`.

After training, evaluate the saved PINNs and generate field plots:

```bash
for problem in convection rd; do
  python -m experiments.evaluate results/$problem/seed42 --gpu 0 --all-levels
  python -m experiments.plot results/$problem/seed42 --output results/$problem/nocl.pdf
done
```

Evaluation regenerates the reference solution and writes `reevaluation.json`
and `prediction.npz`. Use the same accelerator backend as training when checking
checkpoint consistency. Outputs are generated locally and ignored by Git.

## Reference Results

| Experiment | Paper/rebuttal reference | Validated rerun, seed 42 |
| --- | ---: | ---: |
| Convection, alpha = 3 | 0.0970 | 0.0801245794 |
| RD, nu = 4 and rho = 5 | 0.0223053791 | 0.0175693111 |

These are relative L2 errors. Convection retains the source objective
`grad(u) = grad(sin(alpha*(x-30*t)))` with the initial condition on
`[0, 2*pi] x [0, 1]`.

RD solves `u_t - nu*u_xx - rho*u*(1-u) = 0` on `[0,1] x [0,1]`, with
`u(x,0) = sin(pi*x)` and `u(0,t) = u(1,t) = 0`. This is the rebuttal protocol;
the Gaussian experiment in main-paper Table 2 uses a different setup.
The full RD rerun matches a rerun of the original rebuttal script at all 25
stages. Intermediate RD errors use the fixed target reference `(nu,rho)=(4,5)`.
Protocol details are in `experiments/records/rd_protocol.json`.

The measured values above differ from the historical reference values. Hardware,
compiler and dependency changes can alter optimization trajectories. To compare
a completed full run with the reference records:

```bash
python -m experiments.compare results/convection/seed42 results/rd/seed42
```

Reference values are used only for comparison. `--strict` makes the comparison
command return a nonzero exit code if any value differs beyond its tolerance.
